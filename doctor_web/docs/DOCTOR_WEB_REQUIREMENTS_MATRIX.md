**Classification Types (Taxonomy A–H):**
- **A — FULLY IMPLEMENTED**: Verified functional UI, live API endpoint, PostgreSQL persistence, passing tests.
- **B — PARTIALLY IMPLEMENTED**: Partial UI or partial backend integration; requires completing the remaining slice.
- **C — MISSING / NOT IMPLEMENTED**: Explicit client requirement with zero functional frontend UI or route.
- **D — IMPLEMENTED — NOT FUNCTIONAL**: UI exists but has disabled submission, mock timers, or broken handlers.
- **E — UNAPPROVED SCOPE EXPANSION**: Implemented without approved PRD or CR requirement (e.g. Cath Lab, Dental).
- **F — DUPLICATED OR INCONSISTENT**: Redundant route topology or conflicting data models.
- **G — EXTERNAL DEPENDENCY (FLUTTER)**: Scope assigned exclusively to Developer 2's Flutter applications.
- **H — OUT OF SCOPE**: Excluded from Doctor Web (e.g. Pharmacy POS, full Admin Web management).
