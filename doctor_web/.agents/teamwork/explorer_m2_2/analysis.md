## 1. Executive Summary

In Milestone 1, multipart HTTP transmission and live patient demographics resolution were established. In Milestone 2, our objective is to eliminate synthetic mock uploads and ephemeral browser `blob:` Object URLs as substitutes for backend uploads.

This analysis provides the complete architectural design and code-level migration strategy for `src/pages/ocr/MedicalRecordUploadPage.tsx`:
1. **Computer File Upload (`handleFileInputChange`, `handleDrop`, `processSelectedFile`)**: Replace local-only state setting with authentic, asynchronous binary uploads via `attachmentService.uploadAttachment()`, capturing the authentic backend UUID (`id`) and permanent streaming URL (`storageUrl`).
2. **Camera Scan Control (`handleCameraCapture`, video canvas, native capture input)**: Design a unified camera pipeline that handles both native device capture (`capture="environment"`) and video canvas frame extraction (`canvas.toBlob()`), transforming raw frames into authentic JPEG files and uploading them directly to `POST /api/v1/attachments`.
3. **State Binding & Preview Separation**: Redesign `UploadedFileMeta` state to strictly separate the ephemeral client-side visual preview (`blob:...` for local `<img>` display) from the authentic backend attachment metadata (`attachmentId`, `storageUrl`, `storageKey`, `fileName`, `originalName`). Ephemeral `blob:` URLs will NEVER be transmitted to backend persistence endpoints.
4. **Execution Flow Alignment**: In `handleStartProcessing()`, eliminate the hardcoded dummy `'attachment-uuid-1'` and bind the real server attachment ID. In `handleSaveMedicalRecord()`, persist the authentic backend `storageUrl` (`/api/v1/attachments/file/att-...`).

   Because no real upload occurred, the OCR job submission passes a hardcoded dummy string `'attachment-uuid-1'`. In staging, this causes backend validation errors (400 Bad Request or 404 Not Found) because the attachment does not exist.

### 3.3 Camera Capture & Video Canvas Frame Pipeline

To satisfy Target 2 and the E2E test requirements (`feature04_camera_scan_capture.test.ts` and `boundary04_camera_capture_edge.test.ts`):

#### 1. Canvas Frame to Blob/File Conversion:
```typescript
/**
 * Converts an active HTMLVideoElement frame into an authentic JPEG File via HTMLCanvasElement
 */
export async function captureVideoFrameToFile(
  videoElement: HTMLVideoElement,
  customFilename?: string
): Promise<File> {
  const width = videoElement.videoWidth || 1920;
  const height = videoElement.videoHeight || 1080;

  if (width === 0 || height === 0) {
    throw new Error('Video stream dimensions are invalid (0x0). Camera may not be ready.');
  }

  const canvas = document.createElement('canvas');
  canvas.width = width;
  canvas.height = height;

  const ctx = canvas.getContext('2d');
  if (!ctx) {
    throw new Error('Unable to initialize 2D canvas rendering context.');
  }

  // Draw current video raster frame onto canvas
  ctx.drawImage(videoElement, 0, 0, width, height);

  // Convert canvas raster to binary JPEG Blob (92% quality balance)
  const blob = await new Promise<Blob | null>((resolve) => {
    canvas.toBlob(resolve, 'image/jpeg', 0.92);
  });

  if (!blob || blob.size === 0) {
    throw new Error('Captured canvas frame resulted in an empty 0-byte blob.');
  }

  const filename = customFilename || `careid_cam_capture_${Date.now()}.jpg`;
  return new File([blob], filename, { type: 'image/jpeg', lastModified: Date.now() });
}
```

### 3.4 Elimination of Browser Object URLs from Backend Payloads

Requirement R2 and test suite `TC-F06-01` through `TC-F06-05` strictly dictate that browser `blob:` Object URLs must never serve as backend storage references.

#### Two-Zone Architecture:
1. **Client-Only Zone (Ephemeral)**:
   - Location: `uploadedFile.previewUrl` (`blob:http://localhost:5173/3f9a...`).
   - Purpose: Direct rendering in `<img>` on the Review workstation (line 1143) while local editing occurs.
   - Lifetime: Revoked immediately upon document removal, replacement, or page unmount.
2. **Server-Persistent Zone (Authentic)**:
   - Location: `uploadedFile.storageUrl` (`/api/v1/attachments/file/att-787e5187-7859-4320-bb1a-465a57dd086a-1794207446598-scanned-lab-report.png`).
   - Purpose: Stored in backend database via `createMedicalRecord` payload. Streamable via `GET /api/v1/attachments/file/:filename`.
   - Security: Re-fetchable across browser refreshes and multi-device sessions.

#### Defensive Guard in `handleSaveMedicalRecord`:
```typescript
const sanitizeStorageUrl = (url?: string, fileName?: string): string | undefined => {
  if (!url) {
    return fileName ? `/api/v1/attachments/file/${fileName}` : undefined;
  }
  if (url.startsWith('blob:') || url.startsWith('data:')) {
    // Strip client-side URL and construct authentic backend path
    return fileName ? `/api/v1/attachments/file/${fileName}` : undefined;
  }
  return url;
};
```
